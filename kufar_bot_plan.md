# Техническое задание: Telegram-бот парсер объявлений Kufar.by (MVP)

> Этот документ — исполняемая спецификация для AI-агента (Claude Code / Cursor / аналог).
> Следуй разделам по порядку. Каждый этап должен быть проверен (запущен и протестирован) перед переходом к следующему.

---

## 1. Цель проекта

Telegram-бот, который:
1. Позволяет пользователю настроить один или несколько поисковых фильтров по объявлениям Kufar.by (категория, цена, город, доп. параметры категории).
2. Периодически опрашивает API Kufar по каждому сохранённому фильтру.
3. При появлении нового объявления, которое ещё не отправлялось, шлёт пользователю карточку в Telegram (фото + заголовок + цена + ссылка).
4. Не отправляет дубликаты.

Вне рамок MVP (не делать сейчас): избранное, история цен, платные тарифы, мультиязычность, веб-интерфейс.

## 2. Подтверждённые технические факты об API Kufar

**Базовый эндпоинт поиска (подтверждён реальным запросом и ответом):**
```
GET https://api.kufar.by/search-api/v2/search/rendered-paginated
```

**Известные query-параметры (пример для аренды 2-комнатных квартир в Минске, цена 0–450$):**
```
cat=1010                                              # ID категории
cur=USD                                                # валюта фильтра цены
gtsy=country-belarus~province-minsk~locality-minsk    # локация (иерархия через ~)
lang=ru
prc=r:0,450                                            # диапазон цены (r:от,до)
rms=v.or:2                                             # комнаты (v.or: — "любое из списка")
size=30                                                # кол-во объявлений на странице
typ=let                                                # тип сделки (let = долгосрочная аренда)
```

**ВАЖНО — эти параметры агент должен доразведать самостоятельно (см. Этап 1), т.к. они пока не подтверждены:**
- Параметр пагинации для следующей страницы (вероятно `cursor` или похожий, приходит в ответе — искать поле типа `next` / `after` в корне JSON-ответа, не только в `ads`)
- Список ID категорий (`cat=`) для других разделов сайта (авто, электроника и т.д.)
- Названия параметров (`p` / `pu` в JSON) для других категорий — у каждой категории свой набор (площадь, этаж — это специфично для недвижимости)
- Официальных доков нет — весь маппинг категорий и параметров нужно получать эмпирически через DevTools (см. Этап 1) либо через открытый JSON-конфиг сайта, если такой найдётся при разведке.

**Структура одного объявления в ответе (`ads[]`), подтверждено реальным примером:**
```json
{
  "ad_id": 1075551273,
  "ad_link": "https://re.kufar.by/vi/1075551273",
  "subject": "Квартира - студия 40м.2 на длительный срок",
  "body_short": "Квартира-студия...",
  "price_usd": "35000",       // ВНИМАНИЕ: цена в СОТЫХ (35000 = 350.00 USD) — проверить на нескольких примерах
  "price_byn": "101717",
  "currency": "USD",
  "category": "1010",
  "type": "let",
  "list_time": "2026-07-02T18:08:35Z",   // время публикации — ключевое поле для определения "новое ли объявление"
  "phone_hidden": false,
  "images": [
    {"path": "adim1/d8dcac19-....jpg", "media_storage": "rms", "yams_storage": false}
  ],
  "ad_parameters": [
    {"p": "rooms", "pl": "Комнат", "v": "2", "vl": "2"},
    {"p": "size", "pl": "Общая площадь", "v": 40, "vl": "40"},
    {"p": "floor", "pl": "Этаж", "v": [2], "vl": ["2"]}
    // ... разный набор для разных категорий, читать по коду "p"
  ]
}
```

**Сборка URL картинки (нужно подтвердить на Этапе 1, но по открытым источникам формат такой):**
```
https://yams.kufar.by/api/v1/kufar-ads/images/{path}
```
Агент должен проверить на реальном объявлении, что эта ссылка открывается, и при необходимости скорректировать (могут быть разные CDN-хосты для разных media_storage: rms / yams).

**Важные технические риски:**
- API неофициальный, может измениться в любой момент без предупреждения — код должен логировать и не падать при неожиданной структуре ответа (try/except вокруг парсинга полей + запись в лог).
- Возможны рейт-лимиты / бан по IP при частых запросах — заложить паузы между запросами (см. Этап 3) и понятный User-Agent.
- Телефон продавца скрывается (`phone_hidden`) — в MVP не пытаться его доставать.

## 4. Стек

- Python 3.11+
- `aiogram` 3.x — Telegram-бот (FSM для пошаговой настройки фильтра)
- `httpx` (async) — запросы к Kufar API
- `SQLAlchemy` + `SQLite` (для MVP; переход на PostgreSQL — по желанию позже)
- `APScheduler` (AsyncIOScheduler) — периодический опрос
- `python-dotenv` — хранение токена бота и конфигов
- Логирование через стандартный `logging`

## 5. Схема базы данных (MVP)

```sql
users (
  id INTEGER PRIMARY KEY,
  telegram_id BIGINT UNIQUE NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)

subscriptions (
  id INTEGER PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  title TEXT,                    -- человекочитаемое имя фильтра, например "2к квартиры Минск до 450$"
  query_params TEXT NOT NULL,    -- сериализованный dict с параметрами запроса к Kufar API (JSON)
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)

sent_ads (
  id INTEGER PRIMARY KEY,
  subscription_id INTEGER REFERENCES subscriptions(id),
  ad_id BIGINT NOT NULL,
  sent_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(subscription_id, ad_id)
)
```

Хранить `query_params` как JSON, а не отдельными колонками — так как у разных категорий разные наборы параметров, и это избавляет от миграций схемы при добавлении новых категорий.

## 7. Критерии готовности MVP

- Пользователь может через диалог в боте создать фильтр по недвижимости (или другой заранее согласованной категории) с ценой, городом и минимум одним доп. параметром
- Бот присылает новые объявления без дублей в течение согласованного интервала (например, 5 минут)
- Бот не падает при недоступности Kufar API или изменении формата ответа — логирует ошибку и продолжает работать
- Есть возможность посмотреть и удалить свои подписки
